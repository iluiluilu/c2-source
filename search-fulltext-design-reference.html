Thiết kế tính năng Search hiện tại (Toàn văn — OpenSearch + PostgreSQL)

1. Kiến trúc tổng quan

Client (web) --POST /search--> SearchController --> SearchServiceImpl
                                                        │
                                        ┌───────────────┼────────────────┐
                                        ▼                                ▼
                                  OpenSearchClient              PostgreSQL (JPA)
                              (document-v1 / segment-v1)   - ACL double-check (BusinessDataScope)
                                        │                  - hydrate nội dung thật (SearchResultHydrator)
                                        ▼                  - fallback khi OpenSearch mất kết nối
                              SearchResultHydrator ─────────────┘

Hai vai trò tách biệt rõ:

  • OpenSearch = tầng truy hồi/ranking (tìm cái gì khớp, khớp cỡ nào).

  • PostgreSQL = nguồn sự thật cho nội dung hiển thị và quyết định ACL cuối cùng (double-check) — không bao giờ tin tuyệt đối field ACL trong index vì nó có thể lệch/trễ so với Postgres.

2.4 Dữ liệu ghi vào index — nguồn & thời điểm

Không ghi trực tiếp trong request nghiệp vụ; đi qua outbox pattern (đã mô tả ở phiên trước — xem SearchIndexOutboxPoller, poll mỗi 2s theo app.search-index.poll-interval-ms):

outbox_event.event_type Hành động lên index

document.ingested

Upsert document-v1 + 1 pseudo-segment content_source='title' (segment_index=-2) — tài liệu tìm được theo TÊN ngay cả khi chưa OCR/STT xong

review.confirmed / review.reconfirmed

Upsert toàn bộ content_segment (chưa xoá mềm) của run vừa duyệt vào segment-v1, upsert lại document-v1; xoá segment của run bị supersede

document.note.changed

Gộp toàn bộ document_note thành 1 pseudo-segment content_source='note' (segment_index=-1)

document.classification.changed

update_by_query cả 2 index: doc_type, topic_tags

document.acl.changed

update_by_query cả 2 index: scope_group_ids (đọc lại toàn bộ share hiện tại, không áp delta)

Mọi update_by_query dùng script versioned bằng index_version để tránh ghi đè ngược khi event xử lý không đúng thứ tự.

3.1 Predicate ACL double-check (BusinessDataScope.forDocuments)

document.deleted_at IS NULL
AND (
  document.uploader_sub = :currentUserSub
  OR document.id IN (
    SELECT document_id FROM document_group_share
    WHERE group_id IN (:groupIds(user))
  )
)

Đây là bộ lọc quyết định — OpenSearch chỉ lọc sơ bộ theo owner_user_id/ scope_group_ids (có thể lệch nếu index chưa kịp đồng bộ ACL); mọi documentId OpenSearch trả về đều bị áp lại predicate này trước khi vào response, tài liệu không qua được thì bị loại âm thầm (không báo lỗi, không lộ số lượng thật).

4. Luồng truy vấn (SearchServiceImpl.search)

  1. Resolve ScopeContext (userSub + groupIds hiện tại) — lỗi → 403 (ScopeResolutionException), không chạm OpenSearch.

  2. Validate: phải có query hoặc filters (không được cùng rỗng); validate độ dài/số từ query, số lượng từng nhóm filter, docType/confirmSource thuộc danh mục đóng.

  3. effectiveGroupIds = filters.groupIds ∩ ctx.groupIds — id ngoài phạm vi bị loại âm thầm, ghi vào audit (droppedGroupIds), không lỗi.

  4. Build query (SearchQueryBuilder):

    • Có query → simple_query_string trên segment alias, field text^3, text.folded^0.5, text.shingle^2, flags PHRASE|AND|OR|NOT|PRECEDENCE|WHITESPACE (tắt fuzzy/wildcard/regex), default_operator=AND; collapse theo document_id
      inner_hits (tối đa 3 đoạn/tài liệu, sort theo score rồi page_no/time_start_ms tăng dần) + highlight (unified, 1 fragment, 200 ký tự, cắt theo câu).

    • Không có query (chỉ filters) → query thẳng document alias, không collapse, sort uploaded_at desc.

    • Mọi query đều filter bắt buộc ScopeFilterBuilder.build(ctx): owner_user_id = user OR scope_group_ids ∩ groupIds(user) ≠ ∅ (bool.should, minimum_should_match=1).

  5. Over-fetch + double-check: fetchSize = ceil(size × 1.5) + 10; hydrate qua Postgres; nếu số kết quả sau double-check chưa đủ size, lặp thêm 1 vòng (from += fetchSize), tối đa 2 vòng — bù cho việc tài liệu bị ACL double-check loại bớt.

  6. Nếu totalApprox == 0 và có ít nhất 1 filter đang bật → chạy thêm _msearch chẩn đoán (mỗi query bỏ đúng 1 nhóm filter) để sinh refineSuggestions.

  7. Ghi audit search.executed (query đã cắt còn tối đa 200 ký tự, filters, resultCount, sort, droppedGroupIds).

5. API Contract

5.1 POST /search

Quyền: PERM_document.read (đã cấp cho R1/R2, không cấp R3 — giống DocumentsController).

Request body

{
  "query": "hợp đồng thuê nhà",       // string, optional* — tối đa 256 ký tự, tối đa 32 từ (tách whitespace)
  "filters": {                        // object, optional* — *query và filters không được cùng rỗng (400)
    "docType": "Hợp đồng",            // string, 1 giá trị, phải thuộc tag kind=doc_type (400 nếu sai)
    "topicTags": ["Tài chính"],       // string[], tối đa 20, nhãn tag kind=topic
    "topicTagsMode": "AND",           // "AND" | "OR", mặc định "AND"; giá trị khác tự rơi về "AND"
    "uploadedFrom": "2026-08-01",     // date (yyyy-MM-dd), inclusive
    "uploadedTo": "2026-08-31",       // date, inclusive (tự cộng 23:59:59.999 cuối ngày)
    "groupIds": ["<uuid>"],           // UUID[], tối đa 20; giao với nhóm thật của user, phần dư bị bỏ âm thầm
    "folderId": "<uuid>",             // UUID, lọc cả thư mục con
    "mediaType": ["document"],        // ["document"|"audio"|"video"], tối đa 20
    "confirmSource": "manual"         // "manual" | "auto"
  },
  "sort": "relevance",                // "relevance" (mặc định) | "recent"; giá trị khác tự rơi về "relevance"
  "page": 0,                          // integer >= 0, mặc định 0
  "size": 20                          // 1..50 (HARD_MAX=50); mặc định = system-config search.max_results_per_page (20); from+size ≤ 10.000
}

Response body — 200 OK

{
  "results": [
    {
      "documentId": "<uuid>",
      "documentName": "Hợp đồng thuê nhà 2026.pdf",
      "docType": "Hợp đồng",                 // nullable
      "score": 12.34,                         // BM25 score; 0.0 ở nhánh fallback Postgres
      "segments": [                           // tối đa 3, rỗng nếu query rỗng hoặc đang ở fallback
        {
          "segmentId": "<uuid>",              // hoặc "<documentId>:title" / ":note" cho pseudo-segment
          "contentSource": "ocr",             // ocr | stt | sed | summary | note | title
          "confirmSource": "manual",          // manual | auto
          "highlight": "...<em>thuê nhà</em>...",  // nullable
          "position": {
            "type": "page",                   // page | time | none
            "pageNo": 3,
            "lineFrom": 12,
            "lineTo": 15,
            "bboxPolygon": [[0.1,0.2],["..."]],
            "highlightOffsetStart": 120,
            "highlightOffsetEnd": 140,
            "timeStartMs": null,
            "timeEndMs": null
          },
          "sourceReferences": null            // chỉ có giá trị khi contentSource="summary"
        }
      ],
      "documentDigitizationStatus": "confirmed" // nullable — null = chưa từng có run số hoá nào
    }
  ],
  "totalApprox": 137,               // số TÀI LIỆU khớp (ước lượng ở nhánh OpenSearch, chính xác ở nhánh fallback)
  "page": 0,
  "size": 20,
  "degradedMode": "none",           // "none" | "opensearch_unavailable"
  "refineSuggestions": [            // chỉ có khi totalApprox=0 và có filter đang bật
    { "removedFilter": "topicTags", "estimatedCount": 8 }

}

removedFilter chỉ nhận 1 trong 5 giá trị cố định: docType, topicTags, uploadedFrom/uploadedTo, groupIds, folderId/mediaType/confirmSource (3 filter cuối gộp chung 1 nhóm chẩn đoán).
